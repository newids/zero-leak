# Z-LAS 결과물 및 구현 계획

Oct 30, 2026 · @JS Choi

개발 1명, 기획 1명, 마케터 1명이 만 24시간 안에 개발·발표 자료·데모 영상을 끝내는 계획이다. 세 사람 모두 Claude Code·Codex·Gemini를 쓸 수 있으므로, 코드를 쓰는 사람은 세 명이고 설계·통합을 책임지는 사람이 한 명이다. 원칙은 하나다. 시연에 안 보이는 것은 만들지 않는다.

## 1. 전제와 범위 결정

개발 가능 시간은 24시간 중 수면·식사·발표 준비를 뺀 약 16시간이다. AI 코딩 에이전트 덕에 세 사람이 각자 파일 단위로 코드를 만들 수 있지만, 세 결과물을 하나로 잇는 통합은 개발자 한 명의 머리에서만 일어난다. 그래서 범위는 '통합 지점이 적은 구조'를 기준으로 자른다. 기획서의 기술 항목 중 아래 것들은 빼고, 핵심 장면 하나(브라우저가 스스로 비밀번호를 바꾸고 다크패턴을 뚫고 탈퇴하는 장면)에 전부를 건다.

| 기획서 항목 | 24시간 결정 | 이유 |
| --- | --- | --- |
| QLoRA 파인튜닝 + 전/후 벤치마크 | 뺀다 | 데이터 라벨링만 4시간. 대신 A100에서 오픈소스 VLM을 그대로 서빙 |

## 4. 코드 범위와 계약

파이썬 파일 5개와 테스트베드 1개. 사람마다 폴더가 다르고, 폴더끼리는 파일(JSON·PNG)로만 통신한다. 함수 호출로 엮지 않으면 병합이 10분에 끝난다.

| 파일 | 담당 | 핵심 구현 | 예상 시간 |
| --- | --- | --- | --- |
| `testbed/` | 기획자 | Flask 앱 1개, 블루프린트 2개. 쇼핑몰: 로그인 → 마이페이지 → 회원정보 → 비밀번호 재입력 → 변경. 웹하드: 설정 → 계정 → '혜택 유지' 팝업 → '정말 떠나시겠어요' 팝업 → 사유 → 완료. Claude Code에 페이지 흐름 표를 그대로 넣어 생성 | 2.5h |
| `detect.py` | 기획자 | 유출 JSON의 비밀번호를 SHA-256 → 앞 5자리를 볼트 해시 목록과 비교. 매칭 시 변형 규칙(한영 전환, ! @ # 교체, 연도 접미사)으로 후보 재대조 → `risk.json` 출력 | 2h |
| `agent.py` | 개발자 | Playwright → JS 주입(클릭 요소 번호 배지, `type=password` 검은 사각형) → 스크린샷 `shots/step_N.png` → VLM 판단 → 가드레일 → 실행. 최대 12단계, 상태를 `state.json`에 기록 | 5h |
| `llm.py` | 개발자 | OpenAI 호환 클라이언트 하나로 A100 vLLM(기본)과 Claude(승격·가드레일) 호출. 도구: `click(n)`, `fill(n, field)`, `handoff(reason)`, `done()` | 1.5h |
| `app.py` | 마케터 | Streamlit 3열. 왼쪽: 유출 버튼 → `detect.py` 실행 → `risk.json` 그래프. 가운데: `shots/` 최신 PNG 2장 1초 갱신. 오른쪽: 승인 버튼(`approve.flag` 생성), 완료 리포트, 평문 0건 배지. 가짜 데이터로 먼저 완성 | 2.5h |
| `bench.py` | 기획자 | `state.json`에서 소요 시간·단계 수·VLM 응답 시간을 읽어 표 출력 | 0.5h |

### T+1에 확정하는 계약

| 계약 | 내용 |
| --- | --- |
| `leak.json` | `[{email, password_sha256_prefix, source}]` — 기획자가 쓰고 `detect.py`가 읽음 |
| `risk.json` | `[{site, url, risk, reason}]` — `detect.py`가 쓰고 `app.py`·`agent.py`가 읽음 |
| `state.json` | `{site, step, action, status, started_at, finished_at}` — `agent.py`가 쓰고 `app.py`·`bench.py`가 읽음 |
| `shots/step_N.png`, `approve.flag` | 에이전트가 화면을 쓰고 대시보드가 보여줌. 승인은 플래그 파일 존재 여부 |

### AI 코딩 에이전트 사용 규칙

1. 저장소 루트의 `CLAUDE.md` 하나에 계약·폴더 규칙·금지 사항을 적고, 세 사람이 같은 파일을 세션에 넣는다.
2. 요청은 파일 하나 단위로 한다. "대시보드 만들어 줘"가 아니라 "`app.py`: 이 계약의 `risk.json`을 읽어 왼쪽 열에 그래프로"처럼 입력과 출력을 명시한다.
3. 에이전트가 만든 코드는 실행해 본 뒤에만 커밋한다. 실행 안 한 코드는 없는 코드다.
4. 비밀번호·API 키·실제 계정 정보는 프롬프트에 넣지 않는다. 가짜 값으로만 개발한다.
5. 막히면 20분 안에 다른 에이전트(Codex, Gemini)로 같은 요청을 던져 본다. 셋 다 막히면 범위를 줄인다.
6. 분리 실행 증명: `agent.py`는 발표 노트북에서 돌고 비밀번호는 `.env`에서만 읽는다. mitmproxy 캡처에 비밀번호 문자열 0건. 이 캡처 파일이 제출물이다.

## 5. 역할별 산출물

세 사람 모두 코드를 만들지만, 코드가 아닌 산출물의 책임은 바뀌지 않는다.

| 역할 | 코드 | 코드 외 산출물 | 발표에서 맡는 것 |
| --- | --- | --- | --- |
| 개발자 | `agent.py`, `llm.py`, A100 vLLM, 병합·통합, 보안 캡처 | README, 아키텍처 설명 | 기술 질의 응답 |
| 기획자 | `testbed/`, `detect.py`, `bench.py` | 페이지 흐름 표, 유출 JSON, 시나리오 체크리스트, 측정값 표, 레드팀 답변 카드 6장 | 발표자 |
| 마케터 | `app.py` | 서비스 이름·한 줄 소개, 슬라이드 8장, 데모 영상 90초, 자막, 제출 파일 정리 | 데모 조작 |

슬라이드 순서는 심사 기준 그대로 간다. 문제 → 핵심 장면 → 분리 실행 구조(기획서 그림 재사용) → 자체 개발 요소 → 측정값 → 레드팀 Q&A → 팀 → 로드맵. 기획서의 '제출 전 검증 필요 항목'에 있는 출처 없는 숫자는 쓰지 않는다.

## 6. A100 활용

A100은 한 가지 일만 한다. 오픈소스 비전 언어 모델을 vLLM으로 띄워 화면 판단의 1차 호출을 받는 것이다. 설정은 명령 두 줄이고, T+0에 백그라운드로 걸어 두면 T+1 전에 뜬다.

1. Docker로 vLLM 이미지 기동, 모델은 Qwen2.5-VL-7B-Instruct, OpenAI 호환 API 포트 하나만 ACG로 연다.
2. `llm.py`의 기본 엔드포인트를 A100 주소로, 승격·가드레일 엔드포인트를 Claude API로 둔다. 1차 판단의 신뢰도가 낮거나 다크패턴 판별이 필요하면 Claude로 올린다.

발표에서 A100의 역할은 두 문장이다. "화면은 매 단계 외부 API로 나가지 않고 우리 GPU 서버에서 먼저 판단한다", "상용 API는 어려운 판단과 검증에만 쓴다". 비용·보안 두 축에서 설명이 된다.

| 상황 | 대응 |
| --- | --- |
| T+2까지 vLLM이 안 뜸 | 드라이버·이미지 문제로 시간을 쓰지 않는다. `LLM_PROVIDER=claude`로 전환하고 A100은 Streamlit·테스트베드 호스팅용 일반 서버로만 쓴다 |
| vLLM 응답이 3초를 넘김 | 모델을 3B급으로 바꾸거나 이미지 해상도를 절반으로 줄인다 |
| 발표장 네트워크에서 A100 접속 불가 | 노트북 단독 모드(Claude만)로 폴백. T+20에 미리 점검한다 |

## 7. 관문과 포기 순서

관문을 못 넘기면 시간을 더 쓰지 않고 아래 순서로 기능을 뺀다. 빼는 결정은 개발자가 아니라 기획자가 내린다. 만든 사람은 포기를 늦춘다.

| 관문 | 시각 | 못 넘기면 빼는 것 |
| --- | --- | --- |
| G1 테스트베드·대시보드 동작 | T+4 | 웹하드 사이트의 팝업을 2회에서 1회로 |
| G2 쇼핑몰 변경 자율 성공 | T+8 | VLM 1차 판단을 빼고 Claude 단일 호출로 |
| G3 웹하드 탈퇴 성공 | T+12 | 탈퇴 기능을 빼고 '변경' 장면만 2개 사이트로 |
| G4 E2E 1회 성공 | T+18 | 유출 탐지 단계를 하드코딩된 결과로 대체 |
| G5 3회 연속 성공 | T+20 | 라이브 데모를 포기하고 영상 데모로 발표 |

어떤 경우에도 남기는 것: 마스킹 캡처 → 좌표 판단 → 로컬 입력의 분리 실행 구조, 2차 가드레일 호출, 평문 전송 0건 캡처. 이 세 가지가 기획서의 핵심 주장이고, 셋 중 하나라도 빠지면 발표 논리가 무너진다.

## 8. 기획서와 달라지는 점

기획서(서면 심사용)는 2주 규모로 썼다. 본선 결과물이 그보다 작아지는 것은 자연스럽지만, 발표에서 "기획서에는 있는데 왜 없냐"는 질문을 받지 않으려면 아래 문장을 미리 손봐 두어야 한다.

| 기획서 위치 | 현재 문장 | 바꿀 방향 |
| --- | --- | --- |
| 3절 직접 개발 모듈 ② | 데이터셋 1,000건으로 QLoRA 파인튜닝, 전/후 정확도 제시 | "본선에서는 오픈소스 VLM을 그대로 서빙하고, 파인튜닝은 2단계 계획"으로 |
| 3절 직접 개발 모듈 ② | PaddleOCR + YOLO Set-of-Mark | "DOM 기반 번호 배지 주입(자체 구현)"으로. 실제로 더 가볍고 정확하다 |
| 3절 A100 배치표 | 모델 4종 상주, VRAM 분할 | "VLM 1종 서빙"으로 단순화 |
| 4절 정량 목표 | 동시 브라우저 16, 16화면 병렬 | "동시 브라우저 2, 확장 시 16"으로 |
| 4절 정량 목표 | 사이트 10곳 50초 | "사이트 2곳 90초 이내"로 |
| 5절 팀 구성 | AI·비전 / 보안·백엔드 / 클라이언트·에이전트 3인 | 실제 구성(개발·기획·마케터 + AI 코딩 에이전트)으로. 역할 분담표는 이 탭의 5절 |
| 데모 시나리오 | 브라우저 4개 격자, 스마트폰 승인 | 브라우저 2개, 대시보드 승인 버튼 |

반대로 기획서에 없던 강점도 생긴다. "비개발자 2명이 AI 코딩 에이전트로 테스트베드와 대시보드를 직접 만들었다"는 사실은 팀 협업 항목(20점)에서 이야기할 거리가 된다.
