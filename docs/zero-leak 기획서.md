# Z-LAS 서비스 기획서

유출 탐지부터 비밀번호 변경, 서비스 탈퇴까지 한 번에 처리하는 자율 조치 보안 에이전트

Oct 30, 2026 · @JS Choi

## 서비스 개요

Z-LAS(Zero-Leak Action Shield)는 유출 경고를 보여주는 데서 그치지 않고 조치까지 대신 처리하는 서비스다. 비밀번호와 중요정보의 유출을 탐지하면 같은 비밀번호 패턴을 쓴 다른 사이트까지 찾아 비밀번호를 바꾸고, 쓰지 않는 서비스는 탈퇴까지 마친다. 사용자가 할 일은 사이트가 본인인증(캡차·이메일 인증 코드·2FA·PASS)을 요구할 때 그것을 입력하는 것뿐이다. 그 밖의 과정은 전부 자동이며 중간 승인을 받지 않는다(원하면 최종 제출 직전 승인을 설정으로 켤 수 있다).

| 기능 | 사용자가 하는 일 | AI가 하는 일 |
| --- | --- | --- |
| ① 유출 탐지 | 보호할 이메일·계정 목록 등록 | 유출 데이터 감시(본선은 시뮬레이션), k-익명성 해시 대조, 연쇄 위험 사이트 지도 생성 |
| ② 비밀번호 변경 | 변경 대상 선택 → (사이트가 요구할 때만) 본인인증 입력 | 사이트별 변경 메뉴 탐색, 팝업 닫기, 고강도 비밀번호 생성, 입력란 자동 기입·제출, 서버 응답으로 완료 판정, 패스워드 매니저 동기화(2단계) |
| ③ 서비스 탈퇴 | 탈퇴 대상 확인(휴면 3년 이상 자동 추천) | 숨겨진 탈퇴 버튼 탐색, 다크패턴 문구 판별, 약관 체크·사유 입력, 완료 증빙 캡처 |

핵심 설계 원칙은 분리 실행(Split-Execution)이다. 클라우드(네이버클라우드 L4 GPU 서버와 Claude·OpenAI API)는 마스킹된 화면을 보고 어디를 누를지만 판단하고, 비밀번호의 보관과 입력은 사용자 기기 안에서만 이루어진다. 비밀번호 평문은 서버로 전송되지 않는다.

## 1. 기획의 구체성 (20점)

문제의 본질은 유출 사실을 모르는 것이 아니라, 알면서도 조치하지 못하는 데 있다. 브라우저, 운영체제, 보안 앱이 유출 경고를 거듭 띄우지만 실제 조치는 다음 세 가지 장벽에 가로막힌다.

1. 연쇄 감염을 파악할 수 없다. 비밀번호 하나를 조금씩 바꿔 여러 곳에 쓰기 때문에 A 사이트의 유출이 B, C 사이트로 번지는데, 정작 어디에 같은 패턴을 썼는지 사용자는 기억하지 못한다.
2. 변경·탈퇴 경로가 복잡하다. 사이트마다 마이페이지, 회원정보, 본인확인, 보안설정으로 이어지는 순서가 제각각이고, 오래된 사이트는 탈퇴 버튼을 일부러 숨겨 둔다(다크패턴).
3. 기업 보안팀에게 조치 수단이 없다. 임직원이 개인 용도와 업무 용도로 함께 쓰는 계정이 유출돼도 회사가 대신 바꿔 줄 방법이 없다.

## 2. 기획의 창의성 (20점)

기존 보안 서비스는 알림창에서 멈추고, 기존 RPA는 고정된 HTML 태그를 클릭하는 데서 멈춘다. Z-LAS는 이 두 한계를 모두 넘어선다.

1. 사후 경고에서 자율 대리 조치로 전환한다. 보안 서비스의 종착점을 'AI가 브라우저를 직접 조작해 비밀번호를 바꾸고 휴면 계정을 탈퇴시키는 것'으로 다시 정의한다.
2. 분리 실행(Split-Execution) 제로트러스트 구조다. AI에게 비밀번호를 맡기면 그 AI 서버가 가장 큰 표적이 된다는 역설을, 클라우드는 보는 역할(좌표 추론)만, 기기는 손을 움직이는 역할(입력)만 맡는 분리 구조로 해결한다.
3. 연쇄 위험 지도(Domino Risk Map)를 그린다. 유출된 비밀번호 하나에서 한국인의 변형 습관(한영 전환 오타, 특수문자 자리 바꾸기, 연도 붙이기)을 추론해 같은 패턴을 썼을 가능성이 높은 사이트를 확률로 지목한다. 이 연산은 기기 안에서 해시 대조로만 수행한다.
4. 다크패턴을 돌파한다. '혜택을 유지하고 계속 이용하기'와 '포기하고 떠나기' 같은 한국어 함정 문구를 Claude가 행간까지 읽고 올바른 탈퇴 버튼을 고른다. 모델의 한국어 추론 품질이 성패를 가르는 대목이라, 이 단계에만 경량 모델 대신 상위 모델을 쓴다.
5. 인증 넘겨주기(Handoff) 방식이다. 캡차와 본인인증은 우회하지 않는다. 열 단계에 이르는 메뉴 탐색은 AI가 마치고, 인증 팝업만 화면 맨 앞에 띄워 사용자가 5초만 개입하면 되게 한다. 자동화와 적법성을 함께 지키는 설계다.

## 3. 기술 완성도 (20점)

단순히 API를 감싼 서비스가 아니다. 아래 세 모듈은 직접 설계하고 구현하고 학습시키며, 네이버클라우드 L4 GPU 서버와 외부 LLM API(Claude, OpenAI)는 그 토대 위에서 활용한다.

기기는 마스킹된 화면과 해시 앞자리만 보내고, 클라우드는 어디를 누를지 알려 주는 좌표 JSON만 돌려준다. 실제 입력과 비밀번호 보관은 기기 안에서 마무리된다.

### 직접 개발 모듈

| 모듈 | 단순 API 호출 방식 | Z-LAS 직접 개발 내역 |
| --- | --- | --- |
| ① 연쇄 위험 점수기(Domino Risk Scorer) | 유출 문자열과 100% 일치하는 계정만 DB 조회 | 한국인 변형 규칙을 반영한 가중치 키보드 편집거리 알고리즘 + 소형 로컬 LM. 기기 안에서 변형 후보의 해시 트리를 만들어 연쇄 위험도를 확률로 산출. 평문은 기기 밖으로 나가지 않음 |
| ② 한국형 웹 UI 좌표 인식 엔진(Visual Grounding Engine) | 화면 캡처를 멀티모달 API에 넣고 프롬프트로 질문 | DOM에 스크립트를 주입해 클릭 가능 요소마다 번호 배지를 붙이고 비밀번호 입력란을 가리는 Set-of-Mark 전처리기 자체 구현(OCR·객체 탐지 없이 좌표 오차 0). L4에서 오픈소스 VLM(Qwen2.5-VL)을 서빙해 1차 판단을 맡기고, 국내 사이트 UI 데이터셋 기반 QLoRA 파인튜닝은 2단계에서 수행 |
| ③ 위협 필터와 가드레일(유출 분류·인젝션 방어) | 수집 텍스트를 그대로 LLM에 요약 요청 | 보호 대상 계정의 SHA-256 해시 앞자리 대조와 한국형 변형 규칙(한영 전환, 특수문자 교체, 연도 접미사) 기반 연쇄 위험 점수 산출. 웹 화면 속 숨은 명령(간접 프롬프트 인젝션)과 결제·송금·외부 이동 액션을 정규식과 도구 호출(tool use) 스키마 제약으로 원천 차단하는 미들웨어 |

### LLM API 분업 (Claude 기본, OpenAI 대체)

네이버클라우드 해커톤 패키지에는 LLM API가 포함되지 않으므로, 모델 호출은 Claude API를 기본으로 하고 OpenAI API를 대체 경로로 둔다. 두 API 모두 OpenAI 호환 인터페이스로 감싸(LiteLLM 등) 한 줄 설정으로 바꿀 수 있게 한다.

| 단계 | 모델·서비스 | 역할 | 선택 이유 |
| --- | --- | --- | --- |
| 화면 텍스트 좌표 | DOM 스크립트 주입 (로컬 에이전트) | 클릭 요소에 번호 배지 부여, 비밀번호 입력란 마스킹 | OCR·탐지 모델 없이 좌표 오차 0. 화면은 가려진 상태로만 외부에 나감 |
| 화면 이해 | L4 오픈소스 VLM 1차 → Claude 상위 모델 승격 | 마스킹된 화면과 SoM 번호를 보고 몇 번 요소가 비밀번호 변경 메뉴인지 판별 | 매 단계 화면은 자체 GPU에서 먼저 판단하고, 신뢰도가 낮을 때만 상용 API로 올려 비용과 외부 노출을 줄임 |
| 판단·검증 | Claude 상위 모델 (확장 사고 + 도구 호출) | 다크패턴 문구 판별, 탈퇴와 유지 버튼 결정, 도구 호출 스키마로 액션 JSON 강제 출력. 2차 호출에서 해당 액션이 결제·송금·외부 이동에 해당하는지 재검증 | 여러 조건을 동시에 따지는 추론과 JSON 스키마 강제 출력이 필요 |
| 사용자 대화 | Claude Haiku 계열 또는 OpenAI 경량 모델 | 진행 상황 설명, 승인 여부를 묻는 대화, 중장년 사용자를 위한 쉬운 말 안내 | 호출 횟수가 많은 대화는 저비용·고속 모델로 처리 |
| 음성 안내 | OpenAI TTS API | 승인 요청과 완료 안내를 음성으로 | 화면을 보기 어려운 사용자 대응 |

### L4 23GB 상주 모델 배치

| 영역 | 모델·엔진 | VRAM(약) | 역할 |
| --- | --- | --- | --- |
| VLM 서빙 (본선) | vLLM + Qwen2.5-VL-7B-Instruct-AWQ(4비트), OpenAI 호환 API | 약 17 GB (모델 약 6 GB + KV 캐시, 실측) | 화면 판단 1차 호출 |
| 호스팅 (선택) | 테스트베드·대시보드 | — | 발표 노트북 부담 분산 |
| 확장 (2단계) | QLoRA 파인튜닝, 16화면 동시 추론 | GPU 증설 필요 | 서버 증설 후 확장 |

L4의 역할은 둘이다. 본선에서는 매 단계 화면 판단을 자체 GPU에서 먼저 수행해 외부 API 노출과 비용을 줄이고, 2단계에서는 GPU를 증설해 QLoRA 파인튜닝과 화면 16개 동시 추론으로 확장한다. 사용자 한 명이 가입한 사이트는 보통 100개가 넘어 유령 계정 20개를 하나씩 처리하면 30분이 걸리므로, 동시 처리 능력이 실서비스의 핵심이 된다.

## 4. 성과 및 실용 가능성 (20점)

상용화를 가로막는 것은 기술이 아니라 법적 위험과 보안 역설이다. 두 가지 모두 설계 단계에서 해소했다.

### 법적·규제 리스크 해소

- 평문 무저장(Zero-Plaintext): 유출 데이터를 수집할 때 평문을 저장하지 않는다. 수집 즉시 SHA-256 해시로 바꾸고 앞 5자리만 대조하는 k-익명성 프로토콜(HaveIBeenPwned 표준)을 따른다.
- 온디바이스 유사도: qwer1234! 와 qwer1234@ 의 변형 관계 분석은 사용자 기기의 볼트 안에서 해시 대조로만 수행한다.
- 자동화 접근 약관: 데이터센터 IP가 아니라 사용자 본인의 IP와 로그인 세션으로 접속하므로 크리덴셜 스터핑 봇과 구분된다. 캡차와 2단계 인증은 우회하지 않고 사용자에게 넘긴다.

| 서버가 털리면 모든 계정이 한 번에 유출(단일 실패점) | 서버에서 브라우저를 띄워 비밀번호 대리 입력 | 분리 실행: 서버는 마스킹 화면으로 좌표만 추론하고, 입력은 로컬 에이전트가 수행 |
| 봇 탐지(WAF)·FDS 차단 | 클라우드 공인 IP에서 직접 접속 | 사용자 로컬 브라우저 세션과 IP 그대로 사용 |
| 2FA·캡차에서 자동화 중단 | 자동화 실패 | 인증 넘겨주기: 탐색은 AI가 마치고, 인증 팝업만 맨 앞에 띄워 사용자가 한 번만 입력 |
| 악성 페이지의 숨은 프롬프트(간접 인젝션) | 화면 텍스트를 그대로 신뢰 | 액션을 Click·Fill·Check 3종 함수로 제한, 결제·송금·외부 이동 키워드는 Claude 2차 검증 호출(가드레일)이 차단 |
| 유출 평문 보관의 위법성 | 평문 DB 수집·검색 | SHA-256 + k-익명성, 메모리 휘발 |
| 난수 비밀번호로 바꾸면 사용자가 못 외움 | 별도의 폐쇄형 앱 설치를 강요 | Chrome·iCloud 키체인·1Password 호환 포맷으로 즉시 동기화, Passkey 전환 지원 |

## 5. 팀 구성 및 협업 체계 (20점)

개발·기획·마케터 3인이 각자 AI 코딩 에이전트(Claude Code, Codex, Gemini)를 쓰며, 사람마다 담당 폴더가 다르고 폴더끼리는 JSON 파일로만 통신한다. 코드를 쓰는 사람은 셋, 설계와 통합을 책임지는 사람은 하나다.

| 역할 | 담당 코드 | 코드 외 산출물 | 발표에서 맡는 것 |
| --- | --- | --- | --- |
| 개발자 (설계·통합) | agent.py(번호 배지 주입·마스킹 캡처·액션 루프), llm.py(VLM 1차·Claude 승격·가드레일), L4 vLLM, 병합·통합, 평문 전송 0건 캡처 | README, 아키텍처 설명 | 기술 질의 응답 |
| 기획자 (테스트베드·탐지·측정) | testbed/(쇼핑몰·다크패턴 웹하드), detect.py(해시 대조·연쇄 위험 점수), bench.py | 페이지 흐름 표, 유출 데이터, 시나리오 체크리스트, 측정값 표, 레드팀 답변 카드 | 발표자 |
| 마케터 (대시보드·발표·영상) | app.py(Streamlit 3열 대시보드, 승인 버튼) | 서비스 이름·한 줄 소개, 슬라이드 8장, 데모 영상 90초, 자막 | 데모 조작 |

비개발자 두 사람이 테스트베드와 대시보드를 직접 만든다는 점이 이 팀의 협업 방식이고, 파일 형식 3개와 도구 함수 4개로 이루어진 계약을 첫 1시간에 확정하는 것이 그 전제다.

### 협업 워크플로

1. 계약 우선: 시작 1시간 안에 leak.json·risk.json·state.json 형식과 도구 함수 4개(click, fill, handoff, done)를 확정한다. 이후 세 사람이 각자 폴더에서 서로를 기다리지 않고 병렬로 만든다.
2. 모의 데이터 우선: 대시보드와 테스트베드는 가짜 데이터로 먼저 완성하고, 에이전트가 붙으면 파일만 바꿔 끼운다.
3. 자체 테스트베드: 국내 쇼핑몰·웹하드를 모사한 사이트 2종을 Flask로 띄워, 외부 사이트 차단이라는 변수 없이 알고리즘을 재현 가능하게 검증한다. 심사위원에게는 상용 사이트 공격으로 오해받지 않기 위해 같은 난이도의 테스트베드를 구축했다고 설명한다.
4. 관문 5개: 시작 후 4·8·12·18·20시간 지점에서 통과 여부를 확인하고, 못 넘기면 기획자가 범위 축소를 결정한다. 만든 사람은 포기를 늦추기 때문이다.

## 데모 시나리오 (3분) 및 해커톤 구현 범위

화면을 셋으로 나눈다. 왼쪽에는 유출 탐지와 도미노 맵, 가운데에는 AI가 조작하는 브라우저 2개를 나란히, 오른쪽에는 본인인증 넘겨주기(인증이 뜰 때만 나타남)와 완료 리포트를 배치한다.

| 시간 | 장면 | 화면에 보이는 것 |
| --- | --- | --- |
| 0:00–0:45 | 위기 발생 | 텔레그램 시뮬레이터에 유출 덤프를 올리면 2초 뒤 경보가 울린다. 같은 패턴을 쓴 연쇄 위험 사이트 2곳이 붉은 도미노 그래프로 펼쳐진다 |
| 0:45–2:00 | 자율 조작(핵심 장면) | \[원클릭 일괄 방어\] 버튼을 누르면 브라우저 2개가 동시에 열리고, 커서가 스스로 팝업을 닫고 마이페이지로 들어간다. 번호 배지가 붙은 화면과 VLM이 고른 번호가 나란히 표시된다. 다크패턴 사이트에서 '유지하기' 대신 숨겨진 '탈퇴'를 고르는 순간을 확대해 보여준다 |
| 2:00–2:40 | 끝까지 자동 | 웹하드는 '유지하기' 유인 팝업을 두 번 지나 탈퇴가 완료된다. 쇼핑몰은 멈추지 않고 입력·제출까지 끝내고, 서버 응답으로 완료를 판정한다. 사람이 개입하는 순간은 사이트가 본인인증을 요구할 때뿐이다(실제 사이트 실측: 이메일 인증 코드 1회). 심사위원 앞에서 "사람이 통제한다"를 보이고 싶으면 `CONFIRM_SUBMIT=1`로 최종 제출 직전 승인을 켤 수 있다 |
| 2:40–3:00 | 증빙 | 조치 보고서(변경한 사이트, 탈퇴한 사이트, 탈퇴 완료 화면)를 출력한다. 네트워크 캡처로 비밀번호 평문 전송이 0건임을 보여준다 |

### 해커톤 기간 내 구현 범위

- 포함: 유출 시뮬레이션, 해시 대조, 도미노 맵, 테스트베드 2종(쇼핑몰·다크패턴 웹하드) 자율 변경·탈퇴, GPU 서버(L4) VLM 1차 판단과 Claude 승격·가드레일, 본인인증 넘겨주기, 조치 보고서, 평문 전송 0건 캡처.
- 실측(2026-10-31): 실제 상용 사이트(리디북스, 본인 계정, 결제 기능 없음, 팀 합의)에서 로그인 → 마이리디 → 내 정보 관리 → 비밀번호 변경을 12단계·63초에 완주, 평문 전송 0건. 사람 개입은 이메일 인증 코드 입력 1회. Cloudflare 봇 검증은 사용자 PC의 Chrome으로 그대로 통과(위장 없음).
- 제외(2단계로 이관): VLM 파인튜닝, 16화면 병렬 처리, 설치형 데스크톱 앱, 스마트폰 승인 푸시, 실제 상용 사이트 대상 실행, 패스워드 매니저 연동, Passkey 전환.
- 데이터: AI 도구로 생성한 200줄짜리 유출 계정 목록에 표적 계정 3개를 변형 비밀번호로 섞어 넣는다.

## 제출 전 검증 필요 항목

참고한 초안에는 출처가 없는 수치와 가정이 섞여 있다. 그대로 쓰면 심사 질의에서 흔들릴 수 있으므로, 제출 전에 출처를 붙이거나 목표치임을 명시해야 한다.

- [ ] '유출 경고 후 비밀번호 변경 이행률 8.4% 미만': 출처 없음. 공개 조사(예: 구글·하버드 패스워드 체크업 연구, KISA 실태조사)로 대체하거나 삭제
- [ ] '사용자 1인 평균 가입 사이트 100\~150개': 출처 없음. 패스워드 매니저 업체 통계로 교체
- [ ] '계정당 변경 소요 4\~7분', '10곳 45분': 자체 실측값으로 교체(팀원 3명이 직접 재서 평균 기록)
- [ ] L4 VLM 응답 시간 '3초 이내': 본선 시작 1시간 안에 실측 후 숫자 교체
- [ ] QLoRA 파인튜닝: 본선 범위에서 제외했으므로 2단계 계획으로만 언급하고, 현재 문장에 남은 '정확도 향상치' 표현이 없는지 확인
- [ ] 상용 사이트 자동 접속의 약관 위반 소지: 데모는 자체 테스트베드로 한정했음을 명시
- [ ] 네이버클라우드 해커톤 패키지가 실제로 제공하는 GPU 사양과 크레딧: 주최 측 공지 확인 후 3절의 숫자를 맞출 것. LLM API는 패키지에 없으므로 Claude·OpenAI 호출 비용과 호출량 한도를 데모 1회 기준으로 산정해 예산에 반영
