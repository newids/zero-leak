# Zero-Leak 실환경 실행 설정 방법 안내

데모 환경(`mock`)과 달리 **실제 모델이 화면을 보고 판단**하도록 연결하는 방법입니다.
조작 대상은 여전히 테스트베드 2개 사이트뿐입니다 — 실제 사이트에 접속하는 코드는 만들지 않습니다(CLAUDE.md 규칙).

## 1. 구성

```
[사용자 기기]  agent.py ──(마스킹된 PNG + 번호 목록)──►  [네이버클라우드 A100]  vLLM Qwen2.5-VL  ──► click(n) / fill / handoff / done
     │  비밀번호 평문·입력·브라우저는 여기만                     │ 신뢰도 < 0.6 이면 Claude 로 승격 (키 있을 때)
     └─ shared/state.json  summary.plaintext_sent  ◄── llm.MONITOR 가 외부로 나가는 모든 텍스트 검사
```

| `LLM_PROVIDER` | 1차 판단 | 승격 | 필요한 것 |
| --- | --- | --- | --- |
| `mock` | 규칙 | — | 없음 (데모 환경) |
| `vllm` | A100 vLLM (OpenAI 호환) | 신뢰도 < 0.6 → Claude | `VLLM_BASE_URL`, `VLLM_API_KEY`, (선택) `ANTHROPIC_API_KEY` |
| `claude` | Claude, 이미지 입력 | — | `ANTHROPIC_API_KEY` |
| `openai` | OpenAI, 이미지 입력 | — | `OPENAI_API_KEY` |

## 2. A100 서버에 vLLM 띄우기 (개발자, 최초 1회)

네이버클라우드 콘솔에서 GPU 서버(A100 80GB) 생성 → ACG에서 **8000 포트를 팀 IP에만** 허용 → SSH 접속 후:

```bash
git clone https://github.com/newids/zero-leak.git && cd zero-leak
VLLM_API_KEY='팀내부토큰' bash infra/a100_setup.sh       # Docker 로 vllm/vllm-openai + Qwen2.5-VL-7B (다운로드 10~15분)
bash infra/a100_setup.sh check                              # /v1/models 와 샘플 추론 응답시간
```

스크립트가 하는 일: `docker run --gpus all -p 8000:8000 vllm/vllm-openai --model Qwen/Qwen2.5-VL-7B-Instruct --max-model-len 8192 --limit-mm-per-prompt image=1 --gpu-memory-utilization 0.45`.
15분 안에 안 뜨면 붙잡지 않고 `LLM_PROVIDER=claude` 로 갑니다(구현 계획 6절).

확인: `docker logs -f zlas-vllm`, `nvidia-smi`.

## 3. 환경변수 (사용자 기기 쪽)

코드는 `.env` 파일을 **자동으로 읽지 않습니다**(dotenv 미사용). 셸 환경변수로 넣습니다.
`.env.example` 을 복사해 값을 채운 뒤 아래처럼 불러옵니다. `.env` 는 `.gitignore` 에 있어 커밋되지 않습니다.

```bash
cp .env.example .env            # 값 채우기
set -a; source .env; set +a     # Mac/Linux: 현재 셸에 불러오기
```

Windows PowerShell:

```powershell
$env:LLM_PROVIDER="vllm"; $env:VLLM_BASE_URL="http://A100-공인IP:8000/v1"; $env:VLLM_API_KEY="팀내부토큰"
```

| 변수 | 예 | 뜻 |
| --- | --- | --- |
| `LLM_PROVIDER` | `vllm` | 모델 경로 (표 1절) |
| `VLLM_BASE_URL` | `http://A100-IP:8000/v1` | vLLM OpenAI 호환 주소 |
| `VLLM_API_KEY` | `팀내부토큰` | a100_setup.sh 에 준 값과 같아야 함 |
| `VLLM_MODEL` | `Qwen/Qwen2.5-VL-7B-Instruct` | 기본값 그대로 |
| `ANTHROPIC_API_KEY` | `sk-ant-…` | Claude 경로·승격·가드레일 2차 |
| `CLAUDE_MODEL` | 기본값 | 바꿀 일 없음 |
| `OPENAI_API_KEY` / `OPENAI_MODEL` | | OpenAI 경로 쓸 때만 |
| `APPROVE_TIMEOUT` | `60` | 승인 대기 초 (기본 30) |
| `STEP_PAUSE_MS` | `300` | 단계 사이 멈춤. 실모델은 응답 자체가 1~3초라 낮춰도 됨 |

키는 코드·프롬프트·슬라이드·채팅에 절대 붙여넣지 않습니다. 발표 PC에는 발표 직전에 넣고 끝나면 지웁니다.

## 4. 실행

```bash
# 터미널 ①  테스트베드
cd testbed && python app.py

# 터미널 ②  사용자 앱 — 환경변수를 불러온 같은 셸에서 띄워야 에이전트가 물려받는다
set -a; source .env; set +a
cd dashboard && python userapp.py          # [지금 모두 처리하기]가 LLM_PROVIDER 로 에이전트를 띄움

# 또는 에이전트만 직접
cd agent && python agent.py --all --provider vllm
```

관제 대시보드(`streamlit run app.py`)는 왼쪽 사이드바에서 모델 경로를 고를 수 있습니다.

## 5. 연결 점검 순서

1. `bash infra/a100_setup.sh check` 가 JSON 한 줄과 응답 ms 를 찍는가 (A100 쪽)
2. 내 PC에서 `curl -H "Authorization: Bearer $VLLM_API_KEY" $VLLM_BASE_URL/models` 가 200 인가 (ACG·공인 IP)
3. `cd agent && python agent.py --site shop --provider vllm --no-confirm` 의 각 줄 끝 `via vllm` / `via vllm→claude` 확인
4. `python bench.py` → 판단 호출 수·평균 ms·**평문 전송 0건** 표. 이 표가 슬라이드 7장에 들어갑니다.

## 6. 무엇이 외부로 나가는가 (레드팀 대비)

- 나가는 것: `som.js` 가 비밀번호 입력란을 검게 덮은 뒤 찍은 PNG, 번호 붙은 요소 목록(라벨 40자 이내), 현재 경로, 지금까지 누른 요소 이름.
- 안 나가는 것: 비밀번호 평문, 쿠키·세션, 테스트베드 밖 URL.
- 증명: `llm.MONITOR` 가 외부로 나가는 모든 텍스트에서 볼트 비밀번호를 검색하고, `agent.py` 가 브라우저의 외부 요청을 감시해 `state.json → summary.plaintext_sent` 로 합산합니다. 0 이 아니면 종료 코드 2.
- 실모델 응답은 `tool` 이 네 가지(click·fill·handoff·done)가 아니거나 금지어(결제·송금·구매·유지하고…)가 든 요소를 고르면 규칙 가드레일이 막고, Claude 2차 가드레일이 한 번 더 봅니다.

## 7. 장애 시 전환

| 상황 | 조치 |
| --- | --- |
| vLLM 기동 실패·응답 5초 초과 | `LLM_PROVIDER=claude` |
| Claude 키 없음·한도 | `LLM_PROVIDER=openai` |
| 네트워크 자체 불안 | `LLM_PROVIDER=mock` — 흐름·화면·평문 0건 증명은 그대로, "판단 모델만 규칙으로 대체"라고 말하고 진행 |

전환은 환경변수 하나를 바꾸고 터미널 ②를 다시 띄우면 끝입니다. 코드 수정 없음.
