# AI 코딩 에이전트 병행 가이드

Claude Code · Claude Code CLI · Codex · Gemini 에이전트를 세 사람이 동시에 돌려 24시간 안에 Z-LAS를 만드는 방법

Oct 31, 2026 · @JS Choi

에이전트 네 개를 쓰는 팀이 빠른 이유는 타이핑이 빠르기 때문이 아니다. 세 사람이 서로를 기다리지 않기 때문이다. 그래서 이 가이드의 절반은 에이전트 쓰는 법이 아니라 서로 부딪히지 않게 일을 자르는 법이다.

## 1. 도구 4종 역할 분담

네 도구는 비슷해 보이지만 잘하는 일이 다르다. 한 사람이 한 도구만 쓰는 게 아니라, 작업 종류에 따라 도구를 바꾼다.

| 사람 | 보유 플랜 | 주력 도구 | 보조 도구 | 맡는 것 |
| --- | --- | --- | --- | --- |
| 개발자 | Claude Max, Gemini Pro | Claude Code 데스크톱 + CLI (Max라 세션 두 개를 넉넉히 돌림) | Gemini 에이전트: 긴 로그·전체 저장소 읽기, 교차 리뷰, README 초안 | `agent.py`, `llm.py`, L4 vLLM, 통합·병합 |
| 기획자 | Claude Max, ChatGPT Pro | Codex CLI·데스크톱 (Pro라 샌드박스 실행 루프를 제한 없이) | Claude Code: 교차 리뷰, 유출 JSON 생성, 레드팀 답변 카드 | `testbed/`, `detect.py`, `bench.py`, 리뷰 전담 |
| 마케터 | Claude Pro, ChatGPT Plus | Claude Code (Pro는 한도가 작으므로 짧은 세션으로 `app.py`만) | ChatGPT: 슬라이드 본문, 영상 대본·자막, 서비스 카피. Codex(Plus)는 `app.py` 교차 리뷰 한 번 정도 | `app.py`, 슬라이드, 영상 |

도구별로 잘하는 일은 이렇다.

| 도구 | 잘하는 일 | 이 프로젝트에서 쓰는 곳 |
| --- | --- | --- |
| Claude Code (데스크톱·웹) | 긴 작업 위임, 화면 보며 설계 다듬기, 브라우저 확장으로 웹 UI 확인 | `agent.py`(개발자), `app.py`(마케터), 교차 리뷰(기획자) |
| Claude Code CLI | `--worktree` 병렬 세션, `-p` 헤드리스, SSH로 서버에서 직접 작업 | L4 세팅, `llm.py`, 병합(개발자) |
| Codex (ChatGPT Pro·Plus) | 샌드박스에서 테스트 돌려 가며 스스로 고치는 루프, 독립 파일 단위 작업 | `testbed/`, `detect.py`, `bench.py`(기획자), `app.py` 리뷰(마케터) |
| Gemini 에이전트 (Gemini Pro) | 긴 문맥 한 번에 읽기, 저장소 전체 대조, 문서 초안 | 통합 전 형식 불일치 검사, `agent.py` 리뷰, README(개발자) |
| ChatGPT (Pro·Plus) | 비코드 산출물, 카피, 대본 | 슬라이드 본문, 영상 대본·자막(마케터), 레드팀 카드 보조(기획자) |

세 가지 원칙이 있다.

1. 한 파일은 한 도구가 만든다. 같은 파일을 두 도구가 번갈아 고치면 두 도구 모두 상대의 의도를 모른다.
2. 만든 도구와 검토하는 도구를 다르게 한다. Codex가 만든 `detect.py`는 기획자의 Claude Code가, 개발자의 Claude Code가 만든 `agent.py`는 Gemini가, 마케터의 Claude Code가 만든 `app.py`는 Codex가 리뷰한다.
3. 설계·계약·판단은 사람이 한다. 에이전트는 '무엇을'을 정하지 않는다.
4. 한도가 작은 플랜(마케터의 Claude Pro)은 생성에만 쓰고, 리뷰처럼 길게 읽는 일은 한도가 큰 쪽(기획자의 Claude Max, 개발자의 Gemini Pro)에 넘긴다.

## 2. 시작 15분: 공통 세팅

세 사람이 한 화면 앞에 앉아 아래를 함께 한다. 이 15분을 건너뛰면 T+12 병합에서 3시간을 잃는다.

1. 개발자가 저장소를 만들고 폴더를 판다: `agent/`, `testbed/`, `dashboard/`, `shared/`(JSON 계약 파일 위치), `shots/`.
2. `CLAUDE.md`를 루트에 쓰고 `AGENTS.md`, `GEMINI.md`를 같은 파일의 심볼릭 링크(또는 복사본)로 둔다. Claude Code는 CLAUDE.md를, Codex는 AGENTS.md를, Gemini는 GEMINI.md를 세션 시작 때 읽는다. 내용이 하나면 세 도구가 같은 규칙을 안다.
3. `shared/contract.md`에 JSON 파일 형식 3개와 도구 함수 4개를 적고, 예시 파일(`leak.example.json`, `risk.example.json`, `state.example.json`)을 가짜 값으로 만들어 둔다. 예시 파일이 있으면 에이전트가 형식을 틀리지 않는다.
4. `.env.example`에 키 이름만 적는다. 실제 키는 각자 `.env`에 넣고 `.gitignore`에 올린다.
5. 각자 `git worktree`를 하나씩 만들고 자기 폴더에서만 작업한다. 개발자는 `main`을 지킨다.

### CLAUDE.md 템플릿

```
# Z-LAS — 24시간 해커톤 프로젝트

## 무엇을 만드는가
유출된 비밀번호를 탐지해 같은 패턴을 쓴 사이트를 찾고, 브라우저를 자율 조작해
비밀번호 변경·서비스 탈퇴를 대행하는 에이전트. 데모는 테스트베드 2개 사이트에서만.

## 폴더 소유
- agent/     개발자. Playwright 에이전트, LLM 호출 계층
- testbed/   기획자. Flask 테스트베드 2종 (쇼핑몰, 웹하드)
- dashboard/ 마케터. Streamlit 대시보드
- shared/    계약 파일. 바꾸려면 세 사람 합의 후 개발자만 수정
- shots/     에이전트가 쓰는 화면 PNG. 커밋하지 않음

## 폴더 사이 통신은 파일로만
- shared/leak.json  → detect.py 입력
- shared/risk.json  → detect.py 출력, app.py·agent.py 입력
- shared/state.json → agent.py 출력, app.py·bench.py 입력
- shared/approve.flag 존재 = 사용자가 승인함
형식은 shared/contract.md와 *.example.json을 따른다. 임의로 필드를 추가하지 않는다.

## 도구 함수 (llm.py 도구 스키마, 이 네 개만)
click(n) · fill(n, field) · handoff(reason) · done()

## 규칙
- 파이썬 3.11, 의존성은 requirements.txt에만 추가
- 외부 API 키·비밀번호·실제 계정 정보를 코드나 프롬프트에 쓰지 않는다. 가짜 값만
- 테스트베드 외 실제 사이트에 접속하는 코드를 만들지 않는다
- 파일을 만들면 반드시 실행해 보고, 실행 명령과 결과를 응답 끝에 적는다
- 다른 폴더의 파일은 읽기만 한다. 수정이 필요하면 소유자에게 요청 사항을 적는다
- 한 번의 요청에 파일 하나. 두 파일을 동시에 만들지 않는다

## 실행
- 테스트베드: cd testbed && flask run --port 5001
- 대시보드:   cd dashboard && streamlit run app.py
- 에이전트:   cd agent && python agent.py --site shop
```

## 3. 병렬 작업 구조

충돌을 '해결'하려 하지 말고 '불가능'하게 만든다. 방법은 세 겹이다.

| 겹 | 수단 | 효과 |
| --- | --- | --- |
| 저장소 | 사람마다 `git worktree`와 브랜치 하나 (`claude --worktree agent`, `codex`는 해당 worktree 폴더에서 실행) | 같은 파일을 동시에 고칠 수 없음 |
| 폴더 | 소유 폴더 밖의 파일은 읽기만. CLAUDE.md에 명시 | 에이전트가 남의 코드를 '친절하게' 고치는 사고 방지 |
| 인터페이스 | 폴더 사이는 JSON 파일로만 통신, 함수 import 금지 | 병합이 폴더 추가로 끝남 |

### 병합 규칙

1. 병합은 T+12와 T+18 두 번만, 개발자가 한다. 그 사이에는 각자 브랜치에 커밋만 쌓는다.
2. 병합 전 각자 자기 폴더에서 "실행 명령 → 결과"를 커밋 메시지에 적는다. 안 돌아가는 코드는 병합 대상이 아니다.
3. 병합 후 개발자는 Claude Code CLI 한 세션에서 `python agent.py --site shop`을 끝까지 돌리고, 실패하면 그 자리에서 고치지 않고 소유자에게 돌려보낸다. 개발자가 남의 폴더를 고치기 시작하면 통합이 멈춘다.

### 한 사람 안에서의 병렬

개발자는 세션 두 개를 띄운다. 하나는 Claude Code 데스크톱에서 `agent.py` 작업, 다른 하나는 CLI로 L4에 SSH 접속해 vLLM 상태를 보는 세션. Max 플랜이라 둘을 동시에 돌려도 한도 걱정이 적다. 기획자는 Codex로 `testbed/`를 만드는 동안 Claude Code에 유출 JSON 생성을 맡긴다. 마케터는 Claude Code로 `app.py`를 만드는 동안 ChatGPT에서 슬라이드 본문을 뽑고, `app.py`가 끝나면 Claude Code 세션을 닫아 한도를 아낀다. 기다리는 시간에 다른 도구에 다음 일을 걸어 두는 것이 '동시 이용'의 실체다.

## 4. 프롬프트 템플릿 3종

네 도구 모두 같은 형식을 쓴다. 파일 하나, 입력, 출력, 확인 명령. 이 네 줄이 없으면 에이전트는 자기 마음대로 범위를 넓힌다.

### 템플릿 A: 파일 생성

```
파일: testbed/shop/app.py (Flask 블루프린트)
입력: shared/contract.md의 '쇼핑몰 페이지 흐름' 표
출력: 로그인 → 마이페이지 → 회원정보 → 비밀번호 재입력 → 변경 완료, 5개 라우트와 템플릿
제약: 계정은 testbed/seed.json에서 읽는다. CSS는 최소. 다른 폴더 수정 금지
확인: flask run --port 5001 후 브라우저에서 5단계를 손으로 끝까지 진행, 각 단계 URL을 응답에 적어라
```

### 템플릿 B: 수정

```
파일: agent/agent.py
현상: 웹하드 탈퇴 2번째 팝업에서 '유지하기'를 누른다 (shots/step_07.png 참고)
원인 추정: VLM 프롬프트에 '탈퇴 의도'가 빠져 있음
수정 범위: build_prompt() 함수만. 액션 루프는 건드리지 않는다
확인: python agent.py --site webhard 를 돌려 step_07에서 '포기하고 떠나기'를 고르는지 state.json으로 보여라
```

### 템플릿 C: 검토 (만든 도구와 다른 도구에)

```
파일: testbed/detect.py (Codex가 작성)
역할: 리뷰만. 코드를 고치지 말고 문제를 목록으로
관점: 1) shared/contract.md의 risk.json 형식을 지키는가 2) 비밀번호 평문이 로그·출력에 찍히는가 3) 변형 규칙 5종이 모두 테스트되는가
출력: 문제 / 위치 / 심각도(막힘·버그·개선) 표
```

나쁜 프롬프트의 공통점은 '만들어 줘'로 끝난다는 것이다. "대시보드 만들어 줘"는 30분 뒤 Next.js 프로젝트를 받게 되는 요청이다.

## 5. 파일별 레시피

구현 계획 4절의 파일 6개를 어느 도구에, 어떤 순서로, 어떻게 확인하며 시키는지다. 시간은 에이전트 응답 대기를 포함한 사람 기준이다.

| 파일 | 만드는 도구 → 리뷰 도구 | 요청 순서 (한 번에 하나씩) | 확인 | 시간 |
| --- | --- | --- | --- | --- |
| `testbed/` | Codex(기획자) → Claude Code(기획자) | ① 쇼핑몰 블루프린트 5라우트 ② 웹하드 블루프린트 6라우트(팝업 2회 포함) ③ `seed.json` 계정 10개 ④ 두 블루프린트를 묶는 `app.py` | 브라우저에서 손으로 변경·탈퇴 끝까지. 팝업 문구가 기획자 표와 글자까지 같은지 | 2.5h |
| `detect.py` | Codex(기획자) → Claude Code(기획자) | ① 해시 앞 5자리 대조 함수 + 테스트 ② 변형 규칙 5종 생성기 + 테스트 ③ `risk.json` 출력 | `pytest` 통과, 표적 3개 검출, 출력에 평문 없음 | 2h |
| `agent.py` | Claude Code 데스크톱(개발자) → Gemini(개발자) | ① Playwright로 사이트 열고 스크린샷만 ② JS 주입: 클릭 요소 번호 배지, 비밀번호 입력란 마스킹 ③ `llm.py` 호출해 액션 하나 받아 실행 ④ 루프 + `state.json` ⑤ `handoff` 승인 대기 | 각 단계마다 `shots/`에 PNG가 쌓이는지. ③에서 쇼핑몰 1단계 성공, ④에서 끝까지 | 5h |
| `llm.py` | Claude Code CLI(개발자) → Gemini(개발자) | ① OpenAI 호환 클라이언트로 L4 vLLM 호출 ② 도구 스키마 4개 ③ Claude 승격(신뢰도 낮을 때) ④ 가드레일 2차 호출 | 가짜 화면 1장으로 `click(3)` 같은 JSON이 돌아오는지. 결제 버튼 화면을 넣어 가드레일이 막는지 | 1.5h |
| `app.py` | Claude Code(마케터, 짧은 세션 3\~4회) → Codex(마케터, ChatGPT Plus) | ① 3열 레이아웃 + 가짜 데이터 ② `risk.json` 읽어 왼쪽 그래프 ③ `shots/` 최신 PNG 2장 1초 갱신 ④ 승인 버튼이 `approve.flag` 생성 ⑤ `state.json`으로 완료 리포트 | 예시 JSON만으로 화면이 다 그려지는지. 에이전트 없이 먼저 완성 | 2.5h |
| `bench.py` | Codex(기획자) → 리뷰 생략 | `state.json`을 읽어 소요 시간·단계 수·응답 시간을 Markdown 표로 | 샘플 `state.json`으로 표가 나오는지 | 0.5h |

### L4 vLLM (개발자, Claude Code CLI)

SSH로 들어간 터미널에서 `claude`를 띄우고 이렇게 시킨다.

```
이 서버(NVIDIA L4 23GB, Ubuntu, Docker 없음)에 vLLM을 호스트 venv로 띄워라.
모델: Qwen/Qwen2.5-VL-7B-Instruct-AWQ, 포트 8000, OpenAI 호환 API, 이미지 입력 활성화.
확인: curl로 /v1/models 응답과, 샘플 PNG 한 장을 넣은 chat/completions 응답 시간을 보여라.
실패하면 원인만 보고하고 다른 모델로 바꾸지 마라.
```

30분 안에 안 뜨면 `LLM_PROVIDER=claude`로 가고 L4는 호스팅용으로만 쓴다. 구현 계획 6절의 대안표와 같다.

## 6. 검증 루프와 교차 리뷰

에이전트가 만든 코드의 품질은 프롬프트가 아니라 검증 루프가 결정한다. 루프는 세 단계고 전부 15분 안에 돈다.

1. 실행: 템플릿의 '확인' 명령을 에이전트가 직접 돌리게 한다. Codex는 샌드박스에서 알아서 돌리고, Claude Code는 시키면 돌린다. 결과를 응답 끝에 붙이게 한 뒤, 사람은 그 결과만 읽는다.
2. 교차 리뷰: 완성된 파일을 다른 도구에 템플릿 C로 넘긴다. 15분 걸리고, 평균 2\~3개의 실제 버그를 잡는다. 특히 "비밀번호 평문이 어디에 찍히는가"는 만든 도구가 못 보는 문제다.
3. 커밋: 실행 결과와 리뷰 결과를 커밋 메시지에 한 줄씩 적는다. `feat(detect): 해시 대조 — pytest 7 passed, Claude 리뷰 2건 반영`.

### 통합 검증 (T+12, T+18)

개발자가 Claude Code CLI 한 세션에서 아래를 그대로 시킨다.

```
저장소 전체를 읽고, shared/contract.md 기준으로 세 폴더가 주고받는 JSON 형식이
서로 맞는지 검사하라. 불일치는 파일·필드·어느 쪽이 틀렸는지 표로. 코드는 고치지 마라.
```

이 한 번이 병합 충돌보다 훨씬 자주 나오는 '형식 불일치'를 잡는다. 그다음에야 `python agent.py --site shop`을 끝까지 돌린다.

### 자동 리뷰어 (선택, 10분 투자)

`.claude/agents/reviewer.md`에 "계약 준수·평문 노출·범위 이탈 세 가지만 보는 리뷰어"를 서브에이전트로 정의해 두면, 개발자가 매 커밋 전에 `@reviewer`로 한 번씩 돌릴 수 있다. Codex도 같은 내용을 TOML 에이전트로 둘 수 있다.

## 7. 막혔을 때, 보안, 비용

### 막혔을 때의 20분 규칙

1. 같은 요청을 세 번 고쳐서 던지지 않는다. 두 번째 실패에서 멈춘다.
2. 다른 도구에 같은 템플릿을 그대로 넣는다. Claude Code가 막힌 Playwright 문제를 Codex가 풀거나 그 반대인 경우가 흔하다. 도구마다 학습한 코드 분포가 다르기 때문이다.
3. 그래도 막히면 범위를 줄인다. "번호 배지 주입이 안 되면 좌표 대신 CSS 선택자를 VLM에 고르게 한다"처럼 대안을 CLAUDE.md의 규칙 안에서 찾는다.
4. 20분이 지나면 기획자에게 알린다. 포기 결정은 기획자가 한다(구현 계획 7절).

### 에이전트가 자주 틀리는 것

| 증상 | 원인 | 예방 |
| --- | --- | --- |
| 요청한 파일 외에 다른 파일을 '개선'함 | 범위 미지정 | 템플릿의 '수정 범위' 줄, CLAUDE.md의 폴더 소유 |
| JSON 필드 이름을 바꿈 | 계약을 못 봄 | `*.example.json`을 요청에 첨부 |
| 실제 사이트 접속 코드를 만듦 | 테스트베드 개념을 모름 | CLAUDE.md 금지 규칙 + 요청에 `--site shop` 명시 |
| 테스트 없이 "완료"라고 보고 | 확인 명령 없음 | 템플릿의 '확인' 줄은 생략 불가 |
| 의존성을 무더기로 추가 | 편의 우선 | requirements.txt 변경은 커밋 전 사람이 확인 |

### 보안

- API 키는 `.env`에만. 에이전트 세션에 키 값을 붙여넣지 않는다. 키 이름만 알려 주면 된다.
- 테스트 계정 비밀번호도 가짜 값으로 통일한다(`Test1234!`). 진짜 비밀번호는 데모 당일에도 쓰지 않는다.
- Codex 샌드박스는 workspace-write 모드로, Claude Code는 권한 질문에 폴더 밖 쓰기를 허용하지 않는다.
- 에이전트에게 `git push`를 시키지 않는다. 커밋까지만 시키고 푸시는 사람이 한다.

### 비용과 한도

- 한도는 사람마다 다르다. 개발자(Claude Max, Gemini Pro)와 기획자(Claude Max, ChatGPT Pro)는 24시간 내내 돌려도 여유가 있고, 마케터(Claude Pro, ChatGPT Plus)는 Claude Code 한도가 몇 시간 단위로 찬다. 마케터는 `app.py` 단계마다 세션을 닫고, 한도가 차면 남은 작업을 기획자의 Claude Max 세션에 템플릿 그대로 넘긴다.
- 긴 세션은 컨텍스트가 부풀어 느려지고 비싸진다. 파일 하나 끝나면 새 세션을 연다. CLAUDE.md가 있으니 잃을 문맥이 없다.
- 교차 리뷰는 한도가 큰 쪽에 몰아준다. `agent.py`·`llm.py` 리뷰는 Gemini Pro, `testbed/`·`detect.py` 리뷰는 기획자의 Claude Max. 마케터의 ChatGPT Plus Codex는 `app.py` 리뷰 한 번에만 쓴다.
- T+0에 각자 플랜의 남은 사용량을 확인하고, 한도 초기화 시각을 타임라인에 적어 둔다. 마케터의 Claude Pro 초기화 시각 직전에 `app.py` 마지막 단계를 배치하면 한 번 더 쓸 수 있다.

## 8. 비개발자용 10줄 요약

기획자와 마케터가 코드를 '만든다'는 건 타이핑이 아니라 아래 열 가지를 한다는 뜻이다.

1. 자기 폴더에서만 일한다. 남의 폴더는 읽기만.
2. 요청은 네 줄: 파일, 입력, 출력, 확인. '만들어 줘'로 끝내지 않는다.
3. 한 번에 파일 하나. 끝나면 새 세션.
4. 에이전트가 "완료"라고 하면 확인 명령 결과를 보여 달라고 한다. 안 보여 주면 완료가 아니다.
5. 내가 직접 실행해 본다. 브라우저에서 눌러 보고, 표가 나오는지 본다.
6. 끝난 파일은 다른 도구에 "고치지 말고 문제만 찾아라"로 넘긴다.
7. 두 번 실패하면 도구를 바꾼다. 세 번째 시도는 없다.
8. 20분 막히면 기획자에게 말한다.
9. 키·비밀번호·실제 계정은 어디에도 쓰지 않는다.
10. 커밋 메시지에 실행 결과 한 줄. 푸시는 개발자가.

이 열 줄을 지키면 비개발자 두 사람이 만든 테스트베드와 대시보드가 T+12에 개발자의 에이전트와 처음 만났을 때, 고칠 것이 '형식 불일치 두세 개'로 끝난다. 그게 24시간이 가능한 이유다.
